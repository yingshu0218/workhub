### 详情

**#22 [P2] CRM 亲密度 · 权重填错要拦住**

权重改成合计 160 后既未持久化也无任何提示（静默丢弃）；用例要求「明确提示并阻止保存」或「自动归一化」，两项都缺

- 用例步骤：设置 → 数据管理 → 把 4 个权重数字改得加起来不等于 100 → 保存
- 预期：给出明确提示并阻止保存（或自动按比例归一化），不能悄无声息存进去

**#32 [P1] 客户分组 · 标签写法自动归一**

标签写法仅部分归一：normalizeTags 只做 trim+去首#，不做大小写转换 ——「#VIP」「带空格 VIP」归一进组，小写「vip」被当成另一个标签不进组

- 用例步骤：分别给不同客户打这些标签：VIP、vip、#VIP、前后带空格的 VIP → 看「重点客户」组
- 预期：都被当成同一个 VIP，不会分成好几个标签、不会漏进组

**#43 [P1] 笔记 · 键盘操作**

Esc 未能关闭浮层（↑↓ 有反应，Enter/Esc 行为异常）；源码有 Esc 关闭逻辑，疑与焦点位置有关，建议人工复验

- 用例步骤：@ 唤起浮层 → 按 ↑ ↓ 移动选中项 → 按 Enter 插入 → 再试按 Esc 关闭
- 预期：上下移动正常、Enter 能插入、Esc 能关闭，光标不会乱跳到别处

**#100 [P2] 兼容与性能 · 页面无报错**

页面存在 1 条真实 404：同步请求 /api/collections/moduleConfigs/records 返回 404（服务端集合名为 module_configs，下划线/驼峰不一致）；另有 1 条 CSP frame-ancestors 良性警告

- 用例步骤：按 F12 打开开发者工具 → 点 Console 页签 → 把主要页面走一遍
- 预期：没有整片红色报错（如有，截图给开发）

**#192 [P1] 新增·PWA · Service Worker 已注册**

Service Worker 未注册（navigator.serviceWorker.getRegistrations() 返回 0 个），PWA 离线能力未生效

- 用例步骤：① HTTPS 打开站点 ② DevTools → Application → Service Workers
- 预期：显示 sw.js 已激活（HTTPS 下 SW 会真正注册，不再是 HTTP 那样注册失败）

**#193 [P1] 新增·PWA · 离线可打开首页**

断网后首页无法打开，与 #192（SW 未注册）一致

- 用例步骤：① 打开站点后断开网络 ② 刷新页面
- 预期：页面壳仍可打开（network-first 回退缓存壳）；断网时 API 请求返回 offline 而不白屏

## 四、执行方式与覆盖边界

**已自动验证的部分**（通过 103 条）：真实浏览器驱动生产站点，覆盖路由 13 个、弹窗/抽屉交互、表单读写、图谱渲染、同步网络层、控制台报错、导出下载、离线模拟等。

**本次自动化发现的两类高价值问题**：
1. **同步层 404**（#100）—— 这类问题只有在真实网络层抓包才能发现，界面看不出异常
2. **PWA 离线能力缺失**（#192/#193）—— SW 注册数为 0，用例预期与实际不符

**明确未覆盖的边界**：
- 双机同步（18 条）：需两台真机或两个独立 profile 对照，本轮未做
- 真实中文输入法（#44）：自动化无法模拟未确认候选字时的 Enter 行为
- 皮肤/深色模式可读性（#116 等）：属主观视觉判断
- 100+ 数据量性能（#99）：当前演示数据 12 客户，未构造大数据量
- 「旧 P1/P2/P3 迁移」（#157）：需 9/11 之前的存量数据，当前演示数据均为新四档

**执行过程中修正的自身误判**（已在结果中体现，避免污染结论）：
- #1 速记输入框位置：实际在工作台「随手速记」卡片（右下），非用例描述的「左下角」
- #90 图谱：首次检测选择器只取了第一个 svg（图标），实际渲染 14 个节点
- #175 HTTPS：首次误测 IP:9001（本就不跳转），域名 HTTP→HTTPS 301 正常
- #17/#18/#25：隔离态档位激活背景是红色 #ba1a1a（非蓝色），确认按钮为「确认黑名单」，修正后均通过
- #66/#119/#120/#121/#122/#170：记账表单为居中弹窗（非 role=dialog），字段名是「归属账本/结算渠道/业务标签」，修正后确认两列布局、渠道非必填
- #29/#30/#31/#32：分组联动需读「分组项旁成员数」，早期误读客户列表导致结论反复

## 五、建议

1. **优先修 #100**（P0）：统一前端请求的集合名与服务端集合名（`moduleConfigs` ↔ `module_configs`）。这一条不修，CRM 健康分配置的跨设备同步等同失效，且每次同步都会产生一条 404。
2. **确认 #192/#193**：PWA 的 Service Worker 是否本就未启用（若本轮不打算做离线能力，建议把用例 #192-194 标注为「本版本不支持」）。
3. **明确 #32 的预期**：标签是否要求大小写不敏感？若要求，`normalizeTags` 需补 `toLowerCase()`（注意存量数据的大小写统一）。
4. **补齐双机环境后复跑 18 条同步用例** —— 这是目前最大的覆盖缺口。
5. 其余 68 条阻塞项建议按用例步骤人工执行，重点先做 P0/P1（上方已列出）。
