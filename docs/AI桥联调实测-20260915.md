## 三、发现的问题（建议排期，非阻塞）

### P1 · 文档与 UI 不一致：token 填写方向是反的

`docs/AI-Agent桥-一体化说明.md`「日常开发」第 3 步让用户「token 填控制台打印的那个」，
但设置页的 token 输入框是 `readOnly`（`src/modules/settings/AiBridgeSection.tsx:150`），**用户根本填不进去**。

**实际可行路径只能反过来**：先在页面「启用 AI 桥」拿到页面生成的 token → 再用该 token 启动 relay：

```bash
# 1) 先起一次（token 随意），打开页面取到「接入 token」文本框的值 T
npm run dev
# 2) 停掉，用 T 重启
WORKHUB_RELAY_TOKEN="T" npm run dev
```

**影响**：新用户按文档操作必然连不上，而失败时 UI 只有「连接中… / 连接失败」，无排障提示（`bridgeToken` 与 relay token 不一致时不报明确原因）。
**建议**：二选一 —— ① 把 token 输入框改为可编辑（粘贴 relay token），或 ② 页面 token 为准，文档改为「用页面 token 启动 relay」，并在 UI 加一句 token 不一致的提示。

### P2 · 白名单域划分有认知落差

`listNotes` / `listNoteFolders` 归 `read` 域而非 `note` 域（`src/agent/schema.ts:493-494`）。
关掉「笔记」域后，笔记**读取**工具仍在清单里。

设计上自洽（读域统一管读），但用户若想「完全禁止 AI 碰笔记」，只关 note 域不够 —— 还得关 read 域，
而那会连带关掉客户/财务/待办的全部读取。
**建议**：至少在设置页说明文案里点明这层关系。

### P3 · 预览阶段不校验入参 schema

用错误参数名（`id` 而非 `todoId`）调用 `todo_deleteTodo`，**预览与取票都成功**，
直到执行才报 `Required` —— 而此时票据已被消费，需重新走一遍预览确认。

**影响**：Agent 参数写错时，用户会被白问一次确认。
**建议**：预览分支里先跑一次 `schema.safeParse(args)`，不合法直接返回可操作错误（附正确参数名），不发预览。
