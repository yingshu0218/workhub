# 可靠提交协议 1（阶段一、二）

本协议服务于个人助手改造的可靠性版本。事件 activities、联系人别名、复合讲述、撤销与新界面属于下一交付，不在本版本冒充完成。

## 写入边界

| 在线入口 | 提交路径 | 旧路径处理 |
|---|---|---|
| Web 生产表单、拖拽、速记、状态切换、回收站、模块配置 | repository → StorageTx 计划 → `/api/workhub/commands` | IndexedDB 仅在服务端成功后更新；断网明确失败 |
| 服务端 MCP 写工具（现有全部业务工具） | 相同 executor/repository → 请求作用域计划 → 同一 PB 事务端点 | 单工具内部多个事务合并为一次真实事务，浏览器可关闭 |
| 浏览器 Agent 桥 | 相同 repository 与 Web 命令适配器 | 生产默认服务端执行器；桥仅为兼容路径，多页稳定选主 |
| PocketBaseAdapter.transaction | 暂存完整计划后一次命令请求 | 删除逐条 POST/PATCH/DELETE 写集合实现 |
| 旧同步引擎、旧 Web/原生安装包、旧集合 REST 与 batch | 服务端集合写规则 Locked | 普通账号无法绕行；原生新版暂为只读，未同步队列保留供导出核对 |
| JSON 存档恢复 | 生产端明确拒绝直接覆盖本地库 | 使用隔离恢复/迁移工具；导出仍可用 |
| 首启/超管/迁移/备份 | 独立管理通道 | 首启创建账号与拥有者绑定在 PB 同一事务；业务端点拒绝超管替代个人身份 |

`npm run dev` 保留本地合成数据模式，不能作为生产路径验证。`isServerFirstWeb()` 下的适配器、生产 ESM 执行器和实际 PB 均有独立自动化证据。业务写入没有新增运行时依赖。

## 数据与原子性

`src/commands/core.ts` 只含数据规则，编译为 PB CommonJS。Node/浏览器负责读取与构建计划，PB JSVM 在 `runInTransaction` 内重新验证拥有者、世代、版本读集、集合扫描水位、金额、关联端点、删除关联、币种及字段，然后提交业务行、operations、operation_effects、agent_events 和删除登记。任何步骤失败全部回滚；Node 多次 HTTP 调用不被称为事务。

当前为一个拥有者。身份来自 PB users 登录态，并在事务内重新读取账号与 command_state.ownerId。普通账号的集合读取也限定该拥有者。初次迁移存量库有多个账号时必须用部署环境变量 `WORKHUB_OWNER_ID` 明确选择既有账号；不猜拥有者、不改账号密码。Agent 部署凭据需为该拥有者的业务账号。各 Agent 独立凭据/能力和撤销授权留给后续交付，当前仍是既有共享 relay token 加服务端域白名单。

operations 唯一键为 `(owner, requestId)`，保存意图指纹、执行计划指纹、世代、状态、提交序号和回执。具体预览状态为 awaiting_confirmation；成功为 committed；后续可扩展 draft/cancelled。effects 含 operationId、tableName、recordId、action、sourceScope、sequence/ordinal、前后版本及必要快照，按操作和对象分别索引。历史迁移不补造 operations。

相同请求相同计划返回原回执。相同请求替换业务参数或实际写入计划明确拒绝。新请求标识允许相同内容真实发生两次。既有记录采用 rev 显式冲突，集合扫描也校验版本集合，禁止把“远端跳过”当保存成功。表单打开时的版本不能被保存前读取悄悄升级。

## API

所有业务端点需要有效拥有者登录态；URL、操作记录和回包不保存凭据。

| 端点 | 职责 |
|---|---|
| `GET /api/workhub/state` | 返回 protocol=1 与 generation |
| `POST /api/workhub/preview` | 事务内保存具体计划和版本，尚不写业务事实 |
| `POST /api/workhub/commands` | 校验并原子提交，回 operationId/requestId/generation/sequence/changes/result |
| `POST /api/workhub/operations/lookup` | 按 requestId、generation、intent 查询已提交或待确认计划 |
| `POST /api/workhub/finance` | 同一读事务中分页并计算全量匹配汇总，按币种分组 |
| `POST /api/workhub/stage-attachment` | 单文件受控暂存，提交计划引用 stageId；只能引用自己且未过期的文件 |
| `POST /api/workhub/initialize` | 仅超管宿主通道；空库判定、建号、绑定拥有者共用一次事务 |

命令结构见 `Command` 类型。UI/Agent 不把本地校验当作权限证明。计划目标目前限制现有 19 张业务表；不是任意集合或 SQL 执行接口。每命令最多 500 个目标、4 MiB、20,000 条读版本；附件单个 5 MiB，暂存最多 128 个、24 小时有效，每小时清理。扩大范围需另行评估与验证，超限返回错误，不静默截断。

财务分页单页最多 50、窗口最多 20,000 条；汇总覆盖整个匹配窗口。返回 generation、sequence、queryKey 和 nextOffset；续页携带原上下文，写入或筛选变化要求刷新。`amount` 仍是兼容主单位，`amountMinor` 是明确最小单位整数，`currency` 随流水固定。CNY/USD/EUR 分开汇总；按流水 ID 去重，关联两个联系人不复制金额。账本已有流水时不能更换币种。超过两位小数的迁移输入中止并报告，不静默舍入。

## MCP 重试与确认

先调用任意服务端读工具取得 generation，再由客户端生成稳定 requestId。调用时在 MCP tools/call 的 `params._meta`（或同级 params）传 `requestId` 与 `generation`。requestId 在首次提交前确定；已持有请求号却缺原世代会被拒绝。中风险工具返回具体预览，包括生成对象 ID、版本、影响计划及 confirmHint；按 hint 调 confirm_preview，再携带同一请求上下文和 confirmToken 提交。

票据同时绑定工具、参数、请求和世代。确认后版本变化会在事务内失败；不会重新选择默认账本或悄悄执行另一份计划。已提交请求在票据过期、消费或进程重启后可先读原回执。旧无请求标识调用不能安全自动重试；确认提交必须携带具体预览的请求号与世代。

Web 同一保存动作由同步 ref 锁阻止双击；记录 ID、创建时间及附件 ID 保留。发出前把完整计划保存在本地 pending 记录中，响应未知时复用原计划；用户字段改变会要求先核对旧结果。未知提交会保护关闭；重新挂载表单时从本地 pending 恢复原输入，并可查询回执或原样重试；REQUEST_REUSED、鉴权和恢复错误不当作已知未提交而丢弃 pending。页面会话固定数据世代，检测恢复后拒绝继续提交旧草稿，提示保护草稿并重新加载核对。完整跨设备离线操作队列不在本版本。

## 删除、缓存与恢复

镜像对齐保留墓碑正文、trashSnapshot 与恢复元数据，新设备也可使用回收站。对齐与提交互斥，未改变行不反复删除重建；对齐失败不能显示已同步。物理删除必须以墓碑为前置，并同事务写最小 deletion_registry。普通 put 不能自动复活已删实体；专用恢复入口检查关系。墓碑不再由独立 cron 在 30 天后无登记物理删除。

永久删除同时擦除该对象 effects 的旧值与新值、历史回执里的正文和待确认计划，旧操作重试只给最小已执行结果。当前没有活动原话等新来源字段；后续加入时必须扩展相同范围的脱敏。最小删除登记不保存业务正文。

`pb_setup/snapshot.py` 提供可验证冷备份与空目标隔离恢复；主库用 SQLite backup API，附件逐文件 SHA-256 清单和 integrity_check。缺库、损坏或拷贝失败不宣称成功、不清旧备份。backup.sh 必须明确 PB_STOPPED=1；运行中的实例使用 PB 原生备份 API，不能热拷贝附件假装一致。

恢复先在隔离 staging 写 RESTORE_REVIEW_REQUIRED，再拷数据、校验并原子落位。升级前备份标记 PRE_COMMAND_SCHEMA，新版迁移生成新世代；新 schema 恢复主动轮换世代。entrypoint 默认拒绝启动待核对的恢复目录。恢复点后的操作和外部删除登记须先核对；登记不可用时保持隔离，不能承诺旧备份自动保留全部隐私清理。跨世代旧请求即使回执不存在也不能自动重做。

## 迁移和验证

`npm run build:server` 构建共享核心和服务端执行器，并校验已部署迁移的冻结指纹；新增 schema 使用独立编号迁移（当前 1794355200 + 1794355201）。部署必须带 pb_hooks、pb_migrations 和 dist-server；仅更新前端不生效。PB 迁移有持久版本检查点，重复启动不新增记录，金额异常整轮回滚。`scripts/migrate-reliability.mjs --pb <路径> --data-dir <已停服目录> --stopped` 默认在快照预演并列出精度异常；加 `--apply` 才迁移原库，保留原始快照。

真实集成命令：`PB_BIN=<0.40.2> npm run test:integration`。它只新建合成临时库，覆盖当前 schema、04218ca 升级前 schema、并发/重启/响应丢失、数据库中途失败、鉴权、确认后冲突、全量财务汇总、附件、删除、防复活和恢复。证据位置见 PROGRESS 和开发测试环境说明。所有生产验证采用 HTTP/MCP/组件自动化，未开启浏览器。
