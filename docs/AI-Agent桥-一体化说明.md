# AI Agent 接入与 MCP 中转概览

本文概述寻鸽工作台当前的 Agent 接入方式和 Relay 传输边界。配对操作见[一键接入说明](./一键接入-Agent说明.md)，工具定义与使用规则见[生成的 Agent 工具目录](./skills/README.md)。

## 新 Agent 的接入主路径

拥有者登录网页后，在“系统设置 → Agent 接入”为每台设备或每个 Agent 命名，并生成十分钟有效、只能兑换一次的配对码。目标客户端通过 HTTP 兑换后，使用响应中的 MCP 地址和独立 token 连接。

每次配对对应一份独立凭据，可在接入记录中单独撤销。服务端只保存凭据散列；使用本仓库安装器时，凭据会按编号保存到目标设备的独立文件，通用 MCP 客户端则应使用自己的安全凭据存储。配对完成后网页可以关闭；只要客户端和服务端可用，Agent 就能继续工作。拥有者修改网页密码不会使已配对的独立凭据失效。

## Relay、工具与本机兼容传输

Relay 在自托管服务端提供标准 MCP Streamable HTTP。业务数据以服务端 PocketBase 为权威。`tools/list` 和生成的工具目录用于发现能力，不代表授权；服务端仍按每个凭据的能力和部署白名单检查调用。需要确认的写入必须由原客户端展示预览、取得用户确认并提交一次性票据；另一客户端不能确认或撤回该预览。

优先让支持 Streamable HTTP 的 Agent 直接连接 Relay。若客户端只支持 `stdio`，可在目标设备本机运行仓库提供的 `relay/mcp-stdio-shim.mjs`，由它读取该设备的独立凭据并转发 MCP 调用。这是兼容传输方式，不需要在服务器额外启动第二套业务服务。具体配置见[一键接入说明](./一键接入-Agent说明.md)。

## 旧版共享浏览器桥

旧共享浏览器桥仅为已配置它的客户端保留兼容。它依赖已登录且保持运行的网页桥，使用共享凭据，不能按设备或 Agent 单独撤销；当前设置页不再提供该入口。新设备或 Agent 应使用上方的独立配对路径。
