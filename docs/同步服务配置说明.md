# 同步服务配置说明 · 人工操作手册

> 面向**人工操作**的分步指南：服务端（PocketBase）+ 前端（寻鸽工作台）如何配置云端同步。
> 每个关键步骤均以 **⚠️ 关键步骤** 高亮标出，按顺序执行即可完成配置。
>
> 背景知识：
> - 架构与首次部署实录见 `docs/部署指南.md`
> - 服务端物料说明见 `pb_setup/README.md`
> - 同步协议（LWW、游标、墓碑）见开发计划 2.3

---

## 0. 操作前核对清单

开始前逐项打勾，缺一项都可能导致后续步骤卡住：

- [ ] 服务器可访问，PocketBase 已安装（或按 `pb_setup/README.md` 第 1 节安装）
- [ ] 管理后台地址可用：`http://<服务器地址>:<端口>/_/`
- [ ] 拿到 `pb_setup/collections.json`（与本仓库最新代码同版本）
- [ ] 已规划好同步账号（每个成员一个 `users` 账号）
- [ ] 前端为包含同步功能的最新构建（`npm run build` 产物）

## 1. 服务端配置（PocketBase）

### 1.1 启动服务

```bash
cd /opt/nexus/pocketbase          # 实际部署路径以部署指南为准
./pocketbase serve --http=0.0.0.0:9001
```

生产环境建议用 systemd 常驻（模板见 `docs/部署指南.md` 第 2 节），并确认 `systemctl status pocketbase` 为 `active (running)`。

> **⚠️ 关键步骤 ①：导入 collections**
>
> 同步的 15 张 collection（14 业务表 + `sync_state`）必须先导入，缺表时前端推送会**静默失败**（部分表 404，其余表看似正常）。
>
> 操作：管理后台 `http://<服务器>:<端口>/_/` → 超管登录 → Settings → **Import collections** → 粘贴 `pb_setup/collections.json` 全文 → 确认导入。
>
> 校验：Collections 列表中应能看到 `workspaces / customers / transactions / notes / noteFolders / todos / todoLists` 等表，且每张业务表都有 `localId`（唯一索引）与 `updatedAt / deleted / tombstonePushed` 字段。

### 1.2 创建同步账号

```text
管理后台 → Collections → users → New record
```

> **⚠️ 关键步骤 ②：为每个成员各建一个 users 账号**
>
> - 这里的账号是**同步账号**，不是管理后台的超管，两者不能混用。
> - 前端设置页填的就是这个邮箱 + 密码。
> - 本期语义：2 名成员 × 多端登录，**同一份团队数据**——多端必须用同一个成员账号，才会互相同步。

### 1.3 验证服务端就绪

```bash
# ① 健康检查
curl http://127.0.0.1:9001/api/health            # 期望 {"code":200,...}

# ② 同步账号登录（返回 token 即鉴权链路 OK）
curl -X POST http://127.0.0.1:9001/api/collections/users/auth-with-password \
  -H 'Content-Type: application/json' \
  -d '{"identity":"user1@nexus.local","password":"<同步账号密码>"}'

# ③ 空表查询（返回 200 与空 items 即导表成功）
curl 'http://127.0.0.1:9001/api/collections/todos/records?perPage=1' \
  -H "Authorization: <上一步的 token>"
```

三步都通过，服务端才算配置完成。**任何一步失败都先解决，不要进入前端配置。**

## 2. 前端配置（每个设备都要做）

入口：**系统设置 → 云端同步**

### 2.1 填写并保存连接

| 字段 | 填什么 | 注意 |
|---|---|---|
| 服务器地址 | `http://<服务器地址>:<端口>`（如 `http://8.153.19.221:9001`） | 不带尾斜杠；Nginx 同域反代场景填域名即可 |
| 账号 / 密码 | 1.2 创建的同步账号 | 密码仅存本机 IndexedDB，不上传同步载荷 |

> **⚠️ 关键步骤 ③：先「保存并连接」再谈同步**
>
> 点击「保存并连接」，前端会保存配置 → 测试连接 → 自动同步一次。
> 预期结果：状态徽章变为 **「已连接 · 已同步」**；失败时按第 4 节排查。
>
> 注意：地址只在**保存时**去掉尾斜杠并生效，改完地址必须重新点「保存并连接」，仅点「测试连接」不会更新已保存的配置。

### 2.2 首次接入：全量推送

> **⚠️ 关键步骤 ④：首次接入服务器必须执行一次「全量推送」**
>
> 位置：设置 → 云端同步 → 「首次接入 / 更换服务器」→ **全量推送**。
>
> - 作用：把本地**全部业务记录（含软删除墓碑）**写入同步队列推送，随后自动拉取远端增量做 LWW 合并。
> - 日常增量同步**不会**上传历史数据，所以首次接入、**更换服务器**、**服务端 Schema 升级补字段**这三种场景都要手动执行一次。
> - 前提：「保存并连接」已成功，按钮才可用。
> - 新设备（服务器已有数据）**不需要**全量推送：首次拉取会全量拉回本地重建，几分钟内完成。

### 2.3 多端接入

其他设备打开前端 → 设置 → 云端同步 → 填**同一服务器地址 + 同一成员账号** → 保存并连接。之后：

- 在线时：写入防抖 2s + 30s 心跳自动双向同步
- 离线时：徽章显示「离线待同步(N)」，恢复联网自动补传

## 3. 日常维护

### 3.1 备份（强烈建议开启）

```bash
chmod +x /opt/nexus/pocketbase/backup.sh
crontab -e
# 加入（每 4 小时，保留 14 天，详见脚本注释）：
# 0 */4 * * * /opt/nexus/pocketbase/backup.sh >> /var/log/nexus-backup.log 2>&1
```

> **⚠️ 关键步骤 ⑤：确认备份 cron 已生效**
>
> 部署完成的当下就配置备份，并手动跑一次 `./backup.sh` 验证产物生成在 `/opt/pocketbase/backups/`（路径以实际部署为准）。恢复步骤见 `backup.sh` 底部注释：停服务 → 拷回 `data.db`（删 `-wal/-shm`）→ 拷回 `storage/` → 起服务。

### 3.2 Schema 升级（应用每次新增字段 / 表时必做）

> **⚠️ 关键步骤 ⑥：升级 collections 后必须「全量推送」补数据**
>
> 服务端 collections **不会静默报错**——遇到未知字段会直接丢弃，造成数据"丢了但不知道"。
> 应用更新后按此三步：
>
> 1. 确认本仓库 `pb_setup/collections.json` 已是最新
> 2. 管理后台 → Settings → Import collections 重新导入（`deleteMissing: false`），重启 PocketBase 使 pb_hooks 生效
> 3. 前端执行一次「全量推送」，用带新字段的本地版本覆盖服务端旧记录

### 3.3 安全建议

- 管理后台 `/_/` 用 Nginx 做 IP 白名单（配置见 `docs/部署指南.md` 第 3 节）
- 建议绑定域名 + HTTPS（HTTP 明文是当前已知遗留，见部署指南「遗留」一节）
- 同步账号用强密码；超管密码与同步账号密码分开管理

## 4. 故障排查速查

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 「保存并连接」失败 | 地址是否可达：`curl http://<服务器>:<端口>/api/health` | 服务器 / 端口 / 防火墙问题 |
| 测试连接提示鉴权失败 | 账号是否为 **users 同步账号**（不是超管） | 回到 1.2 重建账号 |
| 状态长期「离线待同步」 | 服务端 collections 是否齐全 | 回到 ⚠️ 关键步骤 ① 重新导入 |
| 某类数据不同步 | 对应 collection 是否存在、`localId` 唯一索引是否在 | 重新导入 collections 后执行全量推送 |
| 字段升级后数据"变旧" | 是否执行了升级后的「全量推送」 | 见 ⚠️ 关键步骤 ⑥ |
| A 端改了 B 端没变 | B 端是否同一成员账号、是否在线 | 等 30s 心跳，或手动改任意记录触发 |

> 兜底手段：设置 → 数据与安全 → 「导出 JSON 存档」，可随时拿到全量本地备份。

## 5. 快速操作卡（打印友好）

```text
服务端（首次）:
  ① 管理后台导入 collections.json      ← 缺表 = 推送静默失败
  ② users 建同步账号（每成员一个）
  ③ curl /api/health + 登录验证通过

前端（每台设备）:
  ④ 设置 → 云端同步 → 填地址和账号 → 保存并连接
  ⑤ 首次接入 / 换服务器 / Schema 升级后 → 全量推送（一次）

维护:
  ⑥ 备份 cron 就位并手动验证一次
  ⑦ 管理后台加 IP 白名单，尽早补 HTTPS
```
