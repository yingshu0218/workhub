以「从未适配过本项目的标准 MCP Agent」视角，经如下真实链路遍历调用：

```
MCP 客户端（标准 JSON-RPC over WS）
  → relay 子进程（真 RFC6455 帧 + 真 MCP 路由，**非 --dev**）
  → 页面同款 AgentBridge（原样复用，未改动）
  → agentOps（zod 校验 / 白名单 / 风险分级）
```

关键取舍：relay **不带 `--dev`**，因此中/高风险工具必须由 Agent 自己走「预览 → `confirm_preview` 取票 → 带票执行」，不允许靠 dev 自动附票抄近路 —— 这是真实外部 Agent 的处境。

调用策略与真实 Agent 一致：低风险直达；中/高风险先取预览、再取一次性票据、再执行。

## 五、问题清单

### P1-1 · `todo_createTodo` 缺关联校验，静默产生悬挂引用

**现象**：建待办时挂靠不存在的客户或项目，**不报错、直接创建成功**。

**证据**（实测）：

```
FAIL  B1 建待办→挂不存在客户   期望被拒，实际成功：{"todoId":"ws-main:td:ut_L-2Odyk"}
FAIL  B5 建待办→挂不存在项目   期望被拒，实际成功：{"todoId":"ws-main:td:uwCj0uvKZ_"}
```

**对照**（同类场景均已正确拒绝，说明这是**单点遗漏**而非设计取向）：

| 场景 | 结果 |
|---|---|
| `note_createNote` 挂不存在文件夹 | ✅ 拒绝 |
| `note_createNote` 挂不存在项目 | ✅ 拒绝 |
| `project_createProject` 挂不存在客户 | ✅ 拒绝 |
| `crm_addRelation` 目标不存在 | ✅ 拒绝 |
| `todo_updateTodo` 换成不存在客户 | ✅ 拒绝 |
| **`todo_createTodo` 挂不存在客户/项目** | ❌ **静默成功** |

**位置**：`src/agent/executor.ts:295-319`。函数在校验入参后直接构造 `Todo` 记录并 `todoRepo.put(record)`，对 `customerId` / `projectId` / `listId` **未做任何存在性校验**。（`todo_updateTodo` 有校验，`todo_completeTodo` 亦有 `if (!todo || todo.deleted) return err(...)` —— 唯 create 路径缺失。）

**影响面**：

1. 产生指向不存在节点的悬挂引用，与方案 §六 P2 明写的纪律「关联校验前置：挂靠到不存在的客户/项目/文件夹一律拒绝，不产生悬挂引用（图里不出现指向已删节点的边）」直接冲突；
2. CRM 时间线 / 客户图谱会出现孤儿边或空节点；
3. 后续 `listTodos({ customerId })` 会返回「幽灵关联」的待办 —— 用户看到一条声称属于某客户的待办，但该客户并不存在；
4. 若客户曾被删除后重建，待办会静默挂到旧 id 上。

**建议修法**：在 `todo_createTodo` 落库前，按 `todo_updateTodo` 同款方式对 `customerId` / `projectId` / `listId` 逐个做「存在且未删」校验，缺失时返回可操作错误（`客户不存在：xx，请先 resolveEntity 消解`）。可把该校验提取为共用小函数，避免 create / update 两条路径再次漂移。

### P1-2 · 构建期生成器与运行期不一致，skill 文档中 6 个字段失真

**现象**：`docs/skills/*.md` 与 `docs/skills/mcp-tools.json`（静态快照）里，`fin_recordTransaction` 的 6 个关联字段被生成为完全错误的类型。

**证据**（运行期 vs 静态快照，逐字节对比）：

```jsonc
// 运行期 tools/list（正确）
"customerId": {"anyOf":[{"type":"string"},{"type":"array","items":{"type":"string"}}]}

// 静态快照 mcp-tools.json（错误）
"customerId": {"type":"number","enum":[null,null]}
```

同批失真字段：`customerId` / `customerIds` / `todoId` / `todoIds` / `projectId` / `projectIds`（6 个，占 125 个字段中的 6 个）。

**根因**：`scripts/gen-skills.mjs:86-90` 的 `ZodUnion` 分支假设 options 一定是 `ZodLiteral`，直接取 `_def.value`：

```js
if (t === 'ZodUnion') {
  const values = def.options.map((o) => o._def?.value)   // z.string() 没有 value → undefined
  const allString = values.every((v) => typeof v === 'string')
  return { type: allString ? 'string' : 'number', enum: values }  // → {type:'number', enum:[null,null]}
}
```

而运行期 `src/agent/jsonSchema.ts:106-116` 的同名分支**是修好的**（先判 `allLiterals`，非字面量走 `anyOf`）。`gen-skills.mjs` 顶部注释写着「与 `src/agent/jsonSchema.ts` 同口径；生成器内联避免二次打包」，实际上是**一份陈旧的内联拷贝** —— 单源原则被复制粘贴破坏。

产物已确认非过期：连续两次 `node scripts/gen-skills.mjs` 的 `mcp-tools.json` md5 一致，即**当前代码生成出来就是这样**。

**影响面**：

1. 凡以 `docs/skills/` 作为推理上下文的 Agent（这正是该目录的用途），会读到 `customerId` 类型是 `number`、枚举只有 `null` —— 于是**不敢传字符串 id**，或按 number 构造参数直接被 zod 拒绝；
2. `fin_recordTransaction` 的多值关联能力（Issue #140 刚做的升级）对文档消费者**完全不可见**，等于白做；
3. 参数表在 md 里渲染为 `enum(null / null)`，观感上等于「没有可用类型」。

**建议修法**：

1. `gen-skills.mjs` 删除内联实现，改为 `export` 并复用 `src/agent/jsonSchema.ts` 的 `zodToJsonSchema`（esbuild 打包时把该模块一起打进来即可）；
2. 扩 `skill.parity.test.ts`：现在只断言「工具集 / 风险 / 域」三方一致，**不比对 schema 内容** —— 补一条断言，把运行期 `tools/list` 的 `inputSchema` 与 `mcp-tools.json` 逐字段比对，此类漂移才会在 CI 被挡住。

### P2-1 · `listTodos.priority` 被标为必填，实为可选

**现象**：生成的 schema 里 `listTodos` 的 `priority` 出现在 `required` 中，但实际不传也能正常调用。

**证据**：

```
工具契约导出 → listTodos | status:enum, priority*:enum, customerId:string, projectId:string
实测：不传 priority 调用 → 成功返回
```

**根因**：zod 定义为 `.optional().transform(...)`，最外层是 `ZodEffects`；而两处生成器的必填判定都只看最外层类型名：

```js
if (ct !== 'ZodOptional' && ct !== 'ZodDefault') required.push(key)   // ZodEffects → 被当成必填
```

`src/agent/jsonSchema.ts:70-72` 与 `scripts/gen-skills.mjs:68-69` **两边都有此问题**，故运行期与静态快照一致地错。全量扫描 125 个字段，此类误判恰好只有这 1 处。

**影响面**：Agent 依 schema 会强行构造 `priority` 参数。由于该字段在语义上是**过滤器**，Agent 随手填一个值会**意外过滤掉本应返回的待办** —— 这不是「多传一个无害参数」，而是会让查询结果静默变少。

**建议修法**：把必填判定改为「剥掉 `ZodEffects` / `ZodDefault` 包装后再看内层是否为 `ZodOptional`」，两处同步修改（修 P1-2 后只剩一处）。
