## 2. 代码质量审计

### 2.1 P1 —— 架构纪律的两处知情偏离

#### C-1 `settings:changed` 在事务体内 emit（违反 §6.1「事件永在事务之后」）

**证据** `src/repositories/localAdmin.ts:81-103`：`db.transaction` 的 async 回调体即事务体，`eventBus.emit('settings:changed', …)` 落在 `put` 之后、**commit 之前**。若事务回滚，订阅方（`src/shared/effects.ts:170`、`src/modules/crm/graph/themes.ts:165`）已应用一份**未落库**的设置 = 幽灵状态。

**旁证**：全仓其余 6 处 emit 均已严格避开（`repositories/index.ts:123/210/266`、`crm/intimacy/config.ts:92`、`quickCapture.ts:189`），此处是唯一反例。

**建议**：emit 移到 `db.transaction(...)` 返回之后（`config.ts:64-92` 已是同款样板）。

#### C-2 模块 hooks 层绕过 repositories 直写 db（违反 §4「写入口唯一层」）

**证据**：7 个模块文件、约 30 个写函数直接 `db.transaction` + `db.syncQueue.add`，未经 `src/repositories/`。

| 文件 | 事务处数 | 典型函数 |
|---|---|---|
| `src/modules/crm/hooks.ts` | 9 | `createCustomerGroup`/`reorderCustomerGroups`（:479-563） |
| `src/modules/projects/hooks.ts` | 9 | `saveProject`/`deleteProjectCascade`（:179-300+） |
| `src/modules/todo/hooks.ts` | 4 | `createTodoList`/`deleteTodoListCascade`（:38-95） |
| `src/modules/notes/hooks.ts` | 4 | 4 个文件夹写入口（:92-155） |
| `src/modules/finance/hooks.ts` | 4 | `deleteTransactionCascade`/`reorderLedgers`（:62-118） |
| `src/modules/todo/backfill.ts` | 3 | 存量回填 |
| `src/modules/crm/intimacy/config.ts` | 1 | `saveIntimacyConfig`（:64） |

与 `repositories/repository.ts:43-58` 的 `put()` 是**两套实现**；代码注释自称「模块内合法 Dexie 访问层」（`todo/hooks.ts:10`）= **知情偏离**。`noteFolderWrites.test.ts:181` 的防漂移锁**不检测绕过**。

**影响**：这是既定目标「换存储（Tauri SQLite）时 Repository 零破坏迁移」的**真实缺口**——这 30 处不会随适配器迁移。

**建议**：为「列表/分组/排序」类实体补 repository 复合函数并收口（`clearOtherDefaultLedgers` 是现成样板）；或明确把 §4 改成「写入口分两层」并写清边界，别让文档与代码互相打脸。

#### C-3 `crm_addInteraction` 的 `projectId` 未做关联校验 → 悬挂引用（违反 §6.3）

**证据** `src/agent/executor.ts:228-257`：只校验了 `customerId`，`projectId` 原样透传，无 `assertLinks`。而同文件 `todo_createTodo`（:298）、`note_createNote`（:629）、`project_createProject`（:580）**全部**走了关联校验——此处唯一漏网。

**旁证**：`agentOps.alignment.test.ts:100-108` 恰好传了不存在的 `projectId: 'p1'`，却只断言事件载荷、**不断言落库**，把这个 miss 放过了。

**建议**：加 `assertLinks([{ id: d.projectId, table: 'projects', what: '项目' }])`；测试补「projectId 指向不存在项目 → 可操作错误、不落库」。

#### C-4 三个表单抽屉 `save()` 无错误处理（悬浮 rejection）

**证据**（brace 匹配实测）：
- `CustomerFormDrawer.tsx:203-253` 无 try/catch，调用点 `:500` `onClick={save}` 返回的 Promise **无人 catch**
- `LedgerFormDrawer.tsx:65-…` 无 try/catch，调用点 `:189` `onClick={save}`
- `HabitFormDrawer.tsx:84-106` 无 try/catch，调用点 `:236` `onClick={() => void save()}`（`void` 只消警告、不处理 rejection）

落库失败（配额超限 / 隐私模式 / IndexedDB 被回收）→ 用户看到「点保存没反应、抽屉不关」，零提示。对比 `TransactionFormDrawer.tsx:262-264` 有 `catch → setError`，**同类组件两种纪律**。

**建议**：统一补 `try/catch + setError`。

#### C-5 `download.test.ts` 全量并发下 flaky（CI 红灯风险）

**实测**：全量跑 → `src/shared/__tests__/download.test.ts:126/140`「Test timed out in 5000ms」；**单独跑 → 7 passed / 6.80s**。根因：该文件在 describe 作用域 `walk()` 遍历整个 `src` 树（:115-124），全量并发时 I/O 争用拖过 5s 阈值。

**建议**：给这两个 `it` 加 timeout，或把 `walk` 结果缓存到模块作用域只算一次。**当前「测试全绿」的宣称与实跑不符**，会消耗排查信任。

#### C-6 主包 768 KB —— 全部路由页面都在主包里

**证据** `src/app/router.tsx:1-24` **静态 import 全部 24 个页面**，全仓 **0 处 `React.lazy`**（grep `lazy(` = 0）；`dist/index.html` 把所有 chunk 都 `modulepreload`。打开工作台只为了看待办，却要下载设置页(1648行)/关系画布/笔记编辑器(1352行)的全部代码。

**建议**：`React.lazy` + `<Suspense>` 按路由拆包（至少设置页、关系画布、笔记编辑器、财务四个重页），主包可预期下降 40%+。`vite.config.ts` 的 `manualChunks` 只按 `node_modules` 分类、不处理业务代码，故 `index` 溢出。
