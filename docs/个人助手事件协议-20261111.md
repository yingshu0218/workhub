# 个人助手事件与 Agent 协议（第二次交付）

本协议扩展 [可靠提交协议](可靠提交协议-20261111.md)，服务端仍是事实权威。网页、未来 Android 客户端与 WorkBuddy/Codex/Hermes 共用 PocketBase 命令、版本与回执；MCP 接自有 VPS 的同域 `/relay/mcp`。本轮没有新增第三方服务或运行时依赖。

## 事实与兼容

| 对象 | 当前契约 |
|---|---|
| activities | 独立事件；允许无联系人、多联系人、多事项；与流水、待办、笔记、附件通过 canonical links 关联 |
| 时间 | occurredAt 是实际发生时间；recordedAt 是录入时间；timePrecision 为 date/minute/range；timeZone 必填；范围需结束时间。日期使用明确日历校验，不把 2 月 30 日归整成 3 月 |
| 来源 | 每个事件仅保留其 sourceText；不把整段对话复制到所有记录。原话只有 source:read 且显式 includeSource 才返回 |
| 联系人 | name、aliases、preferredName、contactType；公司、职务、联系方式和商务角色可空。相同姓名不会自动合并 |
| 事项 | 复用 projects，增加 aliases；未强制创建业务项目才能记录事件 |
| 金额 | 新协议 amountMinor 是整数分，返回 amountUnit=minor；currency 必填且与账本一致；汇总按币种分组，禁止把不同币种合计 |
| 旧 interactions | 冻结写入。新旧沟通入口均写 activities；旧读取投影由同一函数派生，不能再读冻结正文作当前事实 |

增量迁移 `1794355202_personal_activities.js` 保留原数据库与 generation。历史 ID 映射为 `act-` 加 SHA256(`interactions/<旧ID>`) 前 32 位；sourceTable/sourceId 有唯一约束。旧深链、历史回执引用、links 的两端与 canonical ID、删除快照一并映射。canonical 冲突合并而不平行产生第二条边；旧边身份写入删除登记。历史 recordedAt 不可考时为 0，不伪造录入时间或创建用户通知。

CRM、项目、统计、时间线与旧 Agent 沟通工具通过活动兼容投影读取；全局搜索直接索引活动摘要。JSON schemaVersion=5 导出活动原字段，只保留未映射的旧沟通行，避免多人参与事件重复或精度丢失。它是业务副本，不含服务端操作、凭据、删除登记与旧离线队列；完整恢复仍使用冷备份。

## 共用查询

拥有者会话使用 `POST /api/workhub/personal/query`，正文为 `{name,input}`。MCP 同名工具使用标准 `{name,arguments}`；不依赖顶层私有 `_meta`。旧工具仍接受旧的上下文位置，但同时提供两处不一致的上下文会报错。

| 工具 | 范围与输出 |
|---|---|
| resolve_contacts / resolve_topics | 姓名、别名、身份线索；最多 10 个候选；resolved/ambiguous；不猜同名身份 |
| search_activities | contactId、topicId、日期、q、category、sourceType；联系人与事项为 AND；活动、实际待办状态变化和未被当前匹配活动表示的独立流水共用稳定 source key；不把持久通知再算作一份事件 |
| get_activity | 新 ID 或历史 sourceId；正文分块、来源按需读取、关联和修改历史入口 |
| get_record | 按 table/id 查询原对象；view=relations 或 history 可分别分页 |
| query_tasks | 未完成为默认；支持 done/voided/all、undated/today/overdue；完成、重开、延期都保留同一待办 ID |
| query_finance | 筛选后的全量计数和分币种汇总；分页只作用于显示明细，不作用于汇总；SQL 只返回所需列与聚合结果 |
| get_contact_context | 最近活动、未完成承诺、范围内财务汇总；子列表截断后使用对应查询按该联系人继续 |
| list_operations | 本客户端最近或待确认操作摘要；拥有者可看全部；包含详情入口，不携带整份计划和正文 |
| get_operation | operationId 或 requestId；最小回执、变更引用；view=effects 支持最多 50 条逐页读取，覆盖 500 项复合操作 |
| query_graph | typed table/id，深度最多 2，节点 100、边 200；明确区分事件参与、明确关系、财务关联、承诺来源；证据指向实际事件，不把推断保存成关系 |

普通分页返回 `items/count/truncated/nextCursor/scope/generation/watermark/queryKey/asOf`，每页最多 50 条。游标绑定筛选、客户端、能力、数据世代和水位。续页需原样沿用筛选与游标；有新提交、预览、取消或恢复时，返回 `QUERY_REFRESH_REQUIRED` 或 `RECOVERY_REVIEW_REQUIRED`，从第一页重新查询。相同时间用稳定 ID 排序。关键词与关联筛选均在取页之前进行。

详情的 summary/markdown/desc/note/联系方式按字段白名单分块。默认块 2000 字符、最大 4000，返回 nextOffset/truncated/revision；续读必须带原 generation 和 revision，不能拼接两个版本。列表摘要最多 500 字符，长字段显式标记 truncatedFields。来源另用 sourceOffset/sourceLimit，不能混入摘要投影。relatedQuery/history.query/effectsQuery 给出实际可用查询；按这些入口先取第一页，再携 nextCursor 续页。

图谱是一次有界聚焦，截断时 nextCursor 为 null，continuation 明确使用返回节点的 table/id 重新聚焦或缩小日期；不生成会重复同一张图的假续页游标。已删除的边在数据库限幅前过滤。未授权的节点、证据或正文不返回。

日界待办查询目前支持 Asia/Shanghai 与 UTC；其他时区需明确偏移或绝对时间，未实现的日界规则明确拒绝。大范围事实/汇总最多 20000 条，超限要求缩小范围，不静默抽样。普通写入仅按对象端点、强引用或来源索引读取关联；预览绑定该范围的成员和 rev，提交时在同一事务重查，新增边等幻读也会拒绝。

## 整组预览与提交

| 动作 | 规则 |
|---|---|
| capture | 同一原子操作录入联系人/别名、事项、多个事件、实际收支、承诺及来源关联；报价、开票和预计款不能直接成为实际收入；疑似重复返回证据，需关联已有对象或明确新增 |
| amend | 明确对象及 expectedRev；字段白名单；关系、金额、时间和待办状态在同一事务修正；变更前后摘要有界，长文本明确截断 |
| undo | 指定 operationId，可选择 effectIds；仅当对象仍为原 afterRev 且无后续依赖才撤销；已清理来源不可撤销 |
| merge | 明确两联系人及各自版本；迁移 canonical links、强引用和别名；事实记录保留，来源联系人标记 mergedIntoId |
| delete | 软删除指定对象；删除联系人保留经历、财务和承诺，仅解除引用；每个根快照只记录自身和明确子项这次实际级联的边 |
| purge | 明确范围、版本和影响；清理源正文、冻结旧来源、相关附件与边、历史效果和回执、未提交草稿计划；共享附件/未包含事件需明确共同范围，不能顺手删其他事实 |

HTTP 分别为 `/personal/preview` 与 `/personal/commit`；MCP 为 `preview_<动作>` 与 `commit_<动作>`。请求号在第一次预览前确定：

```json
{"name":"preview_capture","arguments":{"requestId":"用户端生成的稳定请求号","generation":"从查询返回的世代","input":{"activities":[{"key":"event1","title":"沟通结果","summary":"已发生事实","occurredAt":"2026-11-11","timePrecision":"date","timeZone":"Asia/Shanghai"}]}}}
```

预览持久化具体 ID、读版本、范围快照、实际影响、来源范围与计划指纹；业务事实尚未提交。向用户确认这些具体影响后，严格调用返回的 `confirmHint` 取一次性票据，再把 confirmToken 放进提交工具 arguments。票据同时绑定客户端、generation、requestId、参数和计划指纹；票据不能把预览 A 换成 B。拥有者网页明确确认后通过 X-Workhub-Plan 提交相同计划。

提交再次校验身份、撤销状态、版本、范围成员、永久删除登记、强弱引用、金额和币种。业务事实、操作、effects、通知、删除登记共用一个事务；中途实际落库故障整组回滚。events 仅在事务 commit 后可观察。相同请求/意图重试只返回原回执，不重复记账；不同参数沿用请求号报 REQUEST_REUSED。

超时或断线时保留输入和原 requestId/generation，先 get_operation 核对；未知状态不能改请求号重新记账。cancel_operation 仅撤回未提交计划并清掉草稿来源；已提交需要预览 undo。永久清理同时登记活动本身、历史原 ID 和确定性迁移别名，即便缓存客户端切换新旧 ID，也不能把旧来源复活。撤销/重试已清理操作仅返回不含正文的最小回执。

## 独立 Agent 身份

拥有者登录态访问 `POST /api/workhub/agents`，action=issue/list/revoke；签发需名称与明确能力列表。凭据只返回一次，数据库仅存 SHA256；每个客户端独立 id、capabilities、generation、过期/撤销时间。域能力为 activity/crm/project/todo/fin/note/attachment/link/habit/operation/source 的 read/write。来源正文还单独要求 source:read。

Agent 持自己的 Bearer 凭据请求同域 MCP。relay 每次认证、每次工具调用重新验证凭据，PB 每次事务再次验证。公共 arguments 不接受自报 ownerId/clientId/capabilities/授权字段；网页来源文本也不能成为指令。独立凭据不回退到浏览器桥执行。部署域白名单进一步收窄复合计划每一项写入，不能借 read 域工具绕开关闭的财务等写域。

设备授权沿用 `/device/code → /authorize → /device/token`，批准时为该客户端签独立身份，长期 token 只到 CLI，不经页面。旧共享 relay token 仅有一次升级的 7 天过渡期，绑定当时 generation；恢复后不会自动重新开启。撤销某客户端立即影响已有会话、票据和旧回执重试，另一客户端保持可用。

## 迁移、恢复与多端交接

迁移 1794355200、1794355201 已冻结；本轮新增 1794355202，服务端 schema 与 Dexie v18 同步。部署必须先在隔离库做 v1 保留升级、备份恢复、重复启动，再对 devtest 停服冷备份并原库增量升级，不导入空库覆盖数据。已部署迁移继续冻结，修订另起新编号。

冷备份包含数据库、附件及校验清单；隔离恢复轮换 generation，并保留 RESTORE_REVIEW_REQUIRED。核对恢复点后的操作和外部删除登记前不开放入口。v1 恢复再升级也不启用旧共享身份；旧独立身份、游标、预览与请求均不能自动绑定新世代执行。

本轮提供多端可复用的认证、预览/提交、回执、rev、operation sequence、generation 和 deletion_registry。**当前网页仍是周期全量对齐，不是有界增量同步**；现有 convergeFromServer 尚无跨表水位、缓存身份隔离及防乱序覆盖高 rev 的完整新协议。第三次交付负责共用增量通知/拉取、VPS endpoint、前台恢复与 Android 基础接线及多客户端验收。移动离线策略未裁定前只保留缓存和待提交草稿，不显示离线已记账，也不清理旧队列。Android 是未来客户端目标，本轮没有 APK 或真机验证结论。

本轮只实现 `/activities/:id`、历史 `/interactions/:id` 与 `/operations/:id` 的最小详情页面；完整个人时间线、图谱视图、导航和联系人页由第三次交付消费上述同一查询。未运行浏览器或截图验收。

SQL 读取使用 PocketBase 官方 [Database API](https://pocketbase.io/docs/js-database/) 的绑定查询与固定投影；写入仍使用既有命令事务和 Record 校验，未使用 SQL 绕开业务写入口。
