## 0. 开测前必读（3 条硬结论）

**① 版本已对齐，但开测前仍要验一次入口文件名。**
当前线上与本地均为 `assets/index-CwwbnpCn.js`（服务器 09-10 10:00 部署，含今天最后一批：客户分组、财务表单六项、字号相对单位、侧栏皮肤 chrome、待办编辑与排序、智能清单突出）。**每轮换版本后第一件事仍是用例 A1**，历史上有过"备份/schema 导入完成了但前端没覆盖"导致测到旧版的情况。

**② 服务端 Schema 已就位，但全量推送还没补。**
实测服务器已存在 `module_configs`、`customerGroups` 两张新表（PB 0.40.2 服务 active）。但两张表都是**新增同步表**（本地 Dexie v9 / v10），老设备升级后必须各做一次「全量推送」，否则会出现"本地有、服务端没有 / 服务端有、新设备拉不到"的半同步态。

**③ 当前是 HTTP 明文，Service Worker 不注册，PWA 离线缓存未激活。**
所以"刷新没变化"不是 PWA 缓存导致，而是 Nginx 的 immutable 强缓存 —— 每轮换版本后**必须硬刷新（Cmd+Shift+R）或清站点数据**，否则会拿着旧 bundle 报假 bug（这一条是过去最容易误判的点）。

## 4. 测试用例

### A. 部署与环境 🔴

- **A1 版本一致性**：本地 `dist/index.html` 的入口 JS 名 == 线上 `/index.html` 的入口 JS 名。**预期**：完全一致，不一致说明没部署成功。
- **A2 老库升级不丢数据（重要）**：用**已经用过旧版本的浏览器**直接打开新版（不要清 IndexedDB）。**预期**：Dexie 从 v8 升到 v9/v10 无报错弹窗，客户/笔记/待办/流水数据全在，控制台无 `VersionError` / `SchemaDiff` 报错。
- **A3 全新设备冷启动**：换一个干净 profile / 无痕窗口打开 → 配同步 → 全量拉取。**预期**：新表 `moduleConfigs`、`customerGroups` 一并拉到，无 404 表不存在错误。
- **A4 服务端补齐**：老设备完成 A2 后执行一次「全量推送」，服务端检查 `customers.intimacy`、`notes.folderId`、`ledgers.isDefault` 等新字段是否有值。**预期**：旧记录字段被补齐，不再是空。
- **A5 离线降级**：断网打开应用。**预期**：本地模式可用，同步徽章显示未连接，写入不报错。

### B. 同步专项（本项目最高风险区）🔴

- **B1 新表 module_configs 双向同步**：A 机在「数据管理」改一个亲密度等级名称 → 等待心跳 → B 机刷新设置页。**预期**：B 机看到同名，无需重启。
- **B2 新表 customerGroups 同步**：A 机新建分组「重点客户」→ B 机查看 CRM 左侧分组菜单。**预期**：分组出现，名称/规则/排序一致。
- **B3 配置 LWW 冲突**：A、B 两端都离线各改一次亲密度阈值，先后上线。**预期**：`updatedAt` 大者胜，两端最终一致；不出现来回横跳（rev 递增）。
- **B4 离线写入补传**：A 机断网 → 新建 2 个分组 + 改 1 条客户亲密度 → 恢复网络。**预期**：2s 去抖后队列清空，B 机能拉到，无重复记录（id 幂等）。
- **B5 删除同步（墓碑）**：A 机删除一个分组 → B 机。**预期**：B 机该分组消失，不会"删了又复活"。
- **B6 同步徽章三态**：同步中 / 已同步 / 未连接（离线）。**预期**：三态正确，不虚报（这是历史上修过的 bug，重点复看）。
- **B7 大批量首推**：A 机「全量推送」一次（含新表）。**预期**：进度与结果提示正确，PB 端记录数对得上，无单表失败静默跳过。

### C. 客户亲密度（Issue #34）🟠

前置：CRM 有 ≥5 个客户，其中 1 个标记为黑名单。

- **C1 手动 7 档**：客户详情设置 T1~T5、I6、I7 各一次。**预期**：档位与名称正确显示，保存后刷新仍在。
- **C2 隔离态降级留痕**：从 I6/I7 降回普通档位。**预期**：**强制要求填写降级原因 note，note 为空时禁止确认**（这是明确的设计约束，最容易漏测）。
- **C3 算法兜底**：清空某客户手动亲密度，让算法算。**预期**：算法最多推到 T2，**永不自动给出 T1 / I6 / I7**。
- **C4 算法权重与阈值校验**：数据管理页把 4 个权重改成和 ≠100、把阈值改成非单调（如 t2<t3）。**预期**：归一化提示与单调校验拦截生效，给出明确错误文案，不写入非法配置。
- **C5 配置即时生效**：改等级名称后不刷新切到客户详情选择器。**预期**：新名称已生效（走 `moduleConfig:changed` 广播）。
- **C6 图谱消费**：打开 customer-only 图谱。**预期**：节点大小按亲密度档位区分（远近即大小），图例存在且可读；黑名单客户默认不出现在图谱。
- **C7 缩略卡**：hover/点开客户缩略卡。**预期**：亲密度徽章 + 备注正确显示。
- **C8 黑名单开关矩阵**：分别切换 hideInSearch / excludeFromPicker / hideInTimeline。**预期**：⌘K 搜索、关联选择器、客户时间线按开关屏蔽；默认只开「图谱隐藏」。

## 5. 最容易漏掉的 12 个点（按历史经验排序）

1. **没部署就测**（线上 JS 名 ≠ 本地 dist）—— 先跑 A1。
2. **没硬刷新**（Nginx immutable 强缓存），把旧 bundle 的 bug 报成新 bug。
3. **新增同步表只测了单机**：`moduleConfigs`、`customerGroups` 必须两端验，本机对不代表能同步。
4. **全量推送没补旧记录字段**：新字段在老记录上是空的，功能"看起来能用"但数据不全。
5. **隔离态降级留痕**：I6/I7 降回普通档必须填 note、空值禁止确认。
6. **算法不能越权给档**：算法最多 T2，永不给 T1/I6/I7。
7. **IME 中文输入法**：浮层筛选与插入在拼音输入态下的行为（最容易在中文场景翻车）。
8. **编辑保存丢字段**：编辑待办/流水只改一个字段，其余字段被空值覆盖。
9. **切换清单时筛选 Chip 未重置** 与 **新建后视图不可见**（都是修过的老 bug，容易回归）。
10. **默认账本全局唯一**：设第二个默认时第一个要让位。
11. **发票号"消失"是预期**：DB 字段保留，不要当数据丢失上报。
12. **老库升级路径**：必须用"用过旧版本的浏览器"测一次，全新 profile 测不出来。
