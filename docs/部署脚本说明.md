# 寻鸽工作台 · 一键部署脚本说明

`scripts/deploy.mjs` 把「拉代码 → 构建 → 上传 → 导入配置 → 重启服务 → 验证」合并成一次调用，避免手工分步操作。

## 前置准备（一次性）

1. 复制模板并填真实值：

```bash
cp .deploy.env.example .deploy.env
# 编辑 .deploy.env：填 SSH 别名、PocketBase 部署目录、部署超管账号密码、公网地址
```

> `.deploy.env` 与 `.deploy-state` 均已加入 `.gitignore`，**不会入库**。脚本仅在运行时读取，服务器地址/密码不进代码。

## 用法

```bash
node scripts/deploy.mjs            # 推荐：自动判定模式
node scripts/deploy.mjs --full     # 强制导入配置 + 重启
node scripts/deploy.mjs --light    # 跳过配置导入，仅前端+hooks+重启
node scripts/deploy.mjs --force    # 即使已是最新也强行部署
node scripts/deploy.mjs --check    # 只查看待部署变更，不执行
```

## 自动判定的逻辑

| 情况 | 模式 | 动作 |
|---|---|---|
| `pb_setup/` 或 `src/db/db.ts` 有变更 | full | 备份 → **导入 collections** → 推前端+hooks → **重启 PocketBase** → 验证 |
| 其余代码变更（无 schema 变动） | light | 备份 → 跳过导入 → 推前端+hooks → **重启 PocketBase** → 验证 |

> 每次部署都会重启服务（hooks 需重启生效）。`.deploy-state` 记录上次部署 commit，重复执行且无新提交时会提示「已是最新」并退出。

## 远程脚本做了什么（顺序有意固定，勿打乱）

1. 备份 `pb_public/<时间戳>.tar.gz` + `data.db-<时间戳>.bak`
2. 解包 pb_setup，用服务器 python 把 `collections.json` 转成 import 格式（避免中文经 ssh 损坏）
3. **先导入 collections**（PUT `/api/collections/import`，`deleteMissing:false`）——必须在替换 hooks **之前**，否则 PB 热重载会自动重启，import 会撞上重启窗口
4. 推前端静态 + 覆盖 `pb_hooks/main.pb.js`
5. `systemctl restart pocketbase`
6. 验证：服务 active、health、集合数、入口 JS

## 用户仍需要做的事

- **schema 有升级的版本**：部署后在浏览器里做一次「全量推送」，补旧记录的新字段
- **正式上线**：这套流程对应的是当前开发/测试临时环境；正式环境换服务器时更新 `.deploy.env` 即可（应用代码本身不硬编码地址）

## 常见问题

- **`缺少 .deploy.env`**：按模板创建并填写
- **`已是最新`**：上次部署的 commit 与当前 HEAD 相同，用 `--force`
- **入口 JS 不一致警告**：公网 curl 到的入口与本地 dist 不同，通常是浏览器/CDN 缓存，强刷或等缓存过期
