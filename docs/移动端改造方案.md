# 移动端改造方案（按移动原型实现手机端）

> 依据：`design/DESIGN.md`（设计系统唯一事实源）+ 移动端原型 10 屏（Ardot 画布「寻鸽工作台 · 移动端 App 原型」01~10）。
> 目标：让同一份 Web 代码在窄屏上呈现真正的手机形态，而不是把桌面布局硬塞进 390px。
> 状态：**方案待拍板，尚未动代码。**

---

## 1. 现状核查（实测，非推断）

| 项 | 实测结果 |
|---|---|
| **导航壳** | `src/app/AppLayout.tsx`：侧栏**固定 `w-[232px]` 恒显**，零断点类；主区 `h-screen` + `px-8 py-6` |
| **全站响应式** | **并非零**：`sm:` 出现在 12 个文件、`md:` 6 个、`lg:/xl:` 14 个 —— 但都是**散落的顺带适配**，没有系统性移动布局 |
| **弹层** | `design-system/ui.tsx` 的 `Modal` **已自适应**：`<640px` 全屏（`h-full w-full rounded-none`），`≥640px` 居中对话框。8 个模块的抽屉都走它 |
| **viewport** | `index.html` 已有 `width=device-width, initial-scale=1.0` ✅；**缺 `viewport-fit=cover`** → 刘海/圆角屏的 `safe-area` 目前拿不到 |
| **根高度** | 根容器用 `h-screen`（`100vh`）→ 移动浏览器地址栏收放时会**底部裁切**，需换 `100dvh` |
| **布局密度** | 全模块 44 处 `grid-cols-N`（2 列 25 / 4 列 6 / 3 列 6 / 5 列 3 / 7 列 2）；内容区上限 `max-w-[1200px]` |
| **规模** | 20 条路由；模块 TSX 约 **15.7k 行**（最大 SettingsPage 1624 / TodoPage 1565 / NoteEditorPage 1347） |
| **字号基线** | `html { font-size: 14px }` + rem 体系 → 间距/字号会随根字号整体缩放，利于收敛 |
| **平台判定** | `src/platform/env.ts` 已有 `isTauri()`；Tauri 壳（macOS）已跑通 |

**结论：缺的是「移动壳 + 逐页移动布局」，而不是从零开始。** 现有 `sm:` 适配可复用，不需要推翻。

---

## 2. 断点与策略

- **分界 = `md`（768px）**：`<768px` 走移动壳，`≥768px` 走现有桌面壳。
  选 768 而非现有的 640（`sm`）：壳要从「232px 侧栏 + 内容」切成「单列 + 底部 Tab」，768 才是可靠的分水岭；窄于此的平板竖屏也该用移动形态。
- **CSS 优先，JS 兜底**：能靠断点类解决的（侧栏显隐、栅格降列、内边距）一律用 CSS，避免 JS 判定带来的首帧跳变；只有**结构真的不同**（表格→卡片、某控件不适用移动）才用 `useIsMobile()`。
- **桌面端零改动**：本次不动 `≥768px` 的任何像素，验证方式 = 宽屏截图与现状逐像素对比。

## 3. 移动壳（对齐原型 01/07）

```
┌──────────────────────────┐
│ 状态/顶部栏：页面标题 + 同步徽章 │  ← 沿用 SyncBadge（含连通性态）
│                          │
│        内容区（单列）        │  ← 16px 边距，纵向堆叠
│                          │
│              [灵感闪现 FAB] │  ← 悬浮在 Tab 栏之上
├──────────────────────────┤
│ 胶囊底部导航 5 Tab          │  ← 圆角 36 胶囊、白底、阴影
└──────────────────────────┘
```

- 底部导航：**工作台 · 客户 · 财务 · 习惯 · 我的**，激活态 = 蓝底白字（复用原型里的可复用组件口径）。
- 安全区：Tab 栏加 `padding-bottom: env(safe-area-inset-bottom)`；`index.html` 补 `viewport-fit=cover`。
- FAB「灵感闪现」→ 全屏深色态，对应原型 02。

## 5. 分批实施清单

### 批次 A — 移动壳与基线（其余一切的前提）
1. `index.html`：补 `viewport-fit=cover`（安全区可用）。
2. 根容器 `h-screen` → `h-[100dvh]`（消除移动端底部裁切）。
3. `AppLayout`：侧栏改 `hidden md:flex`；新增 `MobileTabBar`（`md:hidden`）；内容区 `px-4 py-4 md:px-8 md:py-6`；主区底部预留 Tab 栏高度。
4. 新增 `useIsMobile()`（`matchMedia('(max-width: 767px)')`）备用。
5. 新增「灵感闪现」FAB（窄屏显示）。

**验收**：桌面端宽屏与现状一致；390px 宽下能切换到 5 个 Tab，页面不裁切、不横向滚动。

### 批次 B — 五个 Tab 主页移动化（按原型 01/03/05/06/07）
| 页面 | 现状形态 | 移动端改法 |
|---|---|---|
| `/` 工作台 | `max-w-[1200px]` + 多卡网格 | 单列纵向堆叠；指标卡 3 列压缩；焦点卡置顶 |
| `/crm` 客户 | 多列/表格 | 顶部搜索 + 健康分筛选 chips + 卡片列表（原型 03） |
| `/finance` 财务 | 多列 + 流水表 | 净流入卡 + 账本 chips + 流水单列（原型 05） |
| `/habits` 习惯 | 网格 | 连击卡 + 21 天热力网格 + 习惯列表（原型 06） |
| `/profile` 我的 | 双栏 | 单列：等级/EXP 卡 + 奖杯墙 + 设置入口（原型 07） |

### 批次 C — 二级页与详情
待办（列表/详情/新建，原型 08~10）、笔记（列表/编辑器）、项目（列表/详情）、客户详情与时间线、设置（长表单）。
**图表类页注意**：`/crm/canvas`、`/crm/:id/graph`（d3 力导向）在窄屏需要单独处理（缩放手势 / 降级为列表入口），不强行塞进小屏。

### 批次 D — 验收
`npm run build` / `npm test` / `npm run lint` 全绿 → 部署测试站 → 浏览器窄屏 + 真机查看。

## 6. 抽屉形态

现有 `Modal` 在 `<640px` 已是**全屏**，能用。原型 10 给的是**底部抽屉**（圆角面板停在下三分之一、主按钮钉底）。

- **选项 1（省事）**：沿用现有全屏 Modal，只把页头与主按钮钉底。
- **选项 2（贴合原型）**：给 `Modal` 增加 `sheet` 变体，`<md` 时改为底部抽屉（`inset-x-0 bottom-0 rounded-t-2xl max-h-[85dvh]`），`≥md` 保持居中对话框。**一处改动，8 个抽屉同时生效。**

倾向 **选项 2**：改动收敛在一个组件，收益是全站一致。

## 7. 风险与「明确不做」

**风险**
1. 五个 Tab 主页各是 500~1600 行的页面，移动化是**逐页细活**，不是改一个类名就完事 —— 批次 B 的实际工作量大于壳。
2. `NoteEditorPage`（1347 行）含 CodeMirror，移动端编辑器需要单独评估。
3. d3 力导向画布在窄屏的手势与性能需实测。
4. 已有 `sm:` 适配与新 `md:` 断点并存，可能出现「640~768 之间」的过渡态怪异 —— 需要在批次 B 逐页校对。

**不做**
- 不引入移动端 UI 框架（React Native / Ionic / Capacitor UI）—— 同一份 React 代码加断点即可。
- 不改路由结构（移动端只用同一套路由，不另建移动路由树）。
- 不在本次改动桌面端视觉。
- 不碰 Agent 桥在移动端的存在性（已裁定：移动端不保留桥）。
