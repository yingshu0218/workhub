## 1. 运行时服务器地址与恢复入口

- 原生首启没有实际服务器默认值；用户在 App 运行时输入 HTTPS 根地址或 IP/端口，拒绝账号、路径、查询及片段。保存后才开始 `/setup/status`、认证与状态请求，改地址不用重编 APK。
- 检查、初始化、登录、改密、认证失败各页均能打开服务器编辑。进入编辑立即取消旧连接、卸载旧业务会话并清除密码/用户名表单输入；各页显示当前服务器，HTTP 调试地址有明确标记。设置页也可修改地址。
- 失败页先判断编辑状态，避免 `unavailable` 遮挡恢复入口。旧站点的 token 按 origin 原样保留供原站再次验证；切换不会把旧输入送到新站点。

## 2. 认证、镜像和输入隔离

- setup、登录、续期、改密、`client-state` 整段操作捕获开始时 endpoint 与连接 epoch；每个异步响应、正文解析和上层续行复验。`SESSION_CHANGED` 不再被 JSON 解析 fallback 或改密后的初始化标记 fallback 吞掉。`client-state` 仅接受严格的 `schema:6`、`syncProtocol:1` 与非空字符串 owner/generation，否则拒绝挂载私人界面。
- `endpointFetch` 禁止重定向，避免 307/308 将密码 JSON 或认证请求转发到另一 origin；请求取消覆盖 header 之后的晚正文。
- 会话对象和 epoch 一起约束镜像：A→B→A 即使相同 server/owner/generation/schema，旧会话对象仍失效。提交回执显式携带起始会话；存储门面在异步适配器初始化之前固定 epoch；Dexie 事务回调末尾复验以回滚切站时的记录和游标。旧草稿、未知请求、旧队列保持原 scope，不自动迁移或重放。
- 当前缓存、旧库核对副本和业务 JSON 导出在入口捕获会话/epoch，逐表读取、附件读取及下载前复验；切站时不把 A 表与 B 草稿混成一份，也不把旧导出标成新站点。导出调用的 MIME/文件名参数顺序已按 `downloadText(content, mime, filename)` 纠正。
- 上层表单和仓储在首次异步预读取前固定操作会话：项目/里程碑、待办清单、客户分组、账本、速记、笔记编辑、沟通投影和回收站等旧输入经读取后若已切站，拒绝进入新站点的 `storage.transaction`/`serverFirst`。笔记编辑草稿立即按原 scope 留存，定时保存与卸载回调沿用原上下文；旧保存不得清掉较新的草稿。
- 切站会取消客户端等待并丢弃晚响应，但无法撤销旧服务器已经接受的变更；未知提交结果留在原站点 scope 供核对，不在新站点自动重放。

## 3. HTTPS 与 Android debug HTTP

- 正式构建默认仅接受 HTTPS；包括历史 localStorage 地址也每次重新规范和校验。未获许可的 HTTP 持久值在 release 视为未配置，不发请求。
- 唯一调试编译常量由 Vite 的三个条件共同生成：`TAURI_ENV_PLATFORM=android`、`TAURI_ENV_DEBUG=true`、`VITE_WORKHUB_ANDROID_DEBUG_HTTP=1`。调试 APK 即使用 Vite production bundle，也不会误依赖 `import.meta.env.DEV`；release 即使意外继承 `VITE_*`，常量仍为 false。App 内还须对当前手填 HTTP origin 明确勾选，换址清除许可，许可不会随凭据迁移。
- 独立构建日志在实际嵌入包内的前端 JS 中确认 debug 编译门为 true；即使 release 前端构建继承了调试环境变量，编译门仍为 false。最终 debug APK Manifest 的 `usesCleartextTraffic=true`，release 合并 Manifest 为 `false`；实际设备网络行为仍待联调。
- 历史 `CHANGELOG.md?raw` 曾让旧正式/测试环境信息进入 Android 包；Android 构建仅将那条旧部署流程概述化，仓库原文和 Web 展示不变。调试前端 bundle 字面扫描确认旧站点域名与 `devtest` 标签均未出现，业务字段 `Customer.tier`、`Interaction.type` 与应用包标识仍保留。
