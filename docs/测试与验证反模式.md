> **为什么单独成文**：全是**亲历代价**换来的判据纪律，值得独立成篇、也便于新会话直接引用。
> 「怎么跑测试、期望基数、防漂移锁清单」见 `docs/测试说明.md`；此处只记**反模式与判据纪律**。

## 0. 测试与验证的反模式（按代价排序，全亲自踩过）
- ⚠️⚠️ **宽交互面禁用「位移类」按压反馈**。`.press:active`=`scale(0.97)`，元素越宽边缘位移越大（行宽 800px → 左右各收缩约 12px）→ 行内 20px 勾选框跟着位移 → pointerup 指针若已在按钮外 **click 不触发**。**判据：宽容器 + 内部有独立可点元素 = 只能用换底色**。`.press`（含 transform）只给窄元素；`.press-flat`（**只做颜色过渡、绝不动 transform**）给列表行/卡片。断言「行根不含 `.press`」须用**词界正则** `/(^|\s)press(\s|$)/`（`includes` 会被 `press-flat` 误判）。⚠️ **jsdom 不做布局/不算命中 → 复现不了此因果**，真机须人眼点一次
- ⚠️⚠️ **「测试全绿」≠「用户能感知」**：CSS 层叠/对比度问题没有单测能发现，**必须看真机**
- ⚠️⚠️ **自己给错误设计写的「理由」比不写注释更危险**：曾把退场行追加到数组末尾，还在**交付说明**里编了理由。**凡自己产出的设计理由，下次必须实测反查。**
- ⚠️⚠️ **「测试了」≠「测了生产路径」**：`useRowExit` 单测传 `duration=0`，生产传 `200` → 线上分支零覆盖。**交付前核对：测试传参 == 生产传参？**
- ⚠️⚠️ **种子数据要覆盖「边界那个」**：行退场测试初版只 seed 单条 → 打勾后走空态整树卸载 → 恰好绕过要验的「多条时退场」
- ⚠️⚠️ **别把「当时的实现」抄成断言**（= 给 bug 上锁）：正确断言是 `['a','b','c']` 而非当时的 `['a','c','b']`。**写断言前问：期望是「应该如此」还是「现在如此」？**
- ⚠️⚠️ **变异校验要先自证生效**（`perl` 移除 `disabled` 没匹配上，差点得出相反结论）｜**手工构造的验证脚本会引入干扰**（要验生成物就直接拿生成物跑）｜**取样会污染被测对象**（观察者别改被测状态）
- ⚠️ 其余：断言别只看「经过过滤的输出」（改用 `clearTimeout` spy）｜测试定位别依赖「第 N 个元素」｜**既是样式锚点又是测试锚点的类不能条件化**（`group`）｜没覆盖 ≠ 安全
