## 二、技术架构

### 2.0 终端路线（用户定案：三阶段）

| 阶段 | 形态 | 存储 | 说明 |
|---|---|---|---|
| 一（本期） | Web 浏览器优先 | IndexedDB + Dexie | React SPA，全功能 |
| 二（过渡） | PWA | 同上 | 仅加 manifest + 基础 SW（约半天），可安装到主屏幕，不深投入 |
| 三（终态） | **Tauri 2 原生 App**：Android / Windows / macOS | 原生 SQLite（tauri-plugin-sql） | 同一套 React 代码装进系统 WebView，安装包 ~10MB；桌面端可注册全局快捷键/托盘 |

**硬性要求**：Phase 0 的 repository 层必须做到存储可插拔——`DexieRepository`（Web）与将来的 `TauriSqliteRepository`（原生）对上层模块与同步引擎完全透明（同步引擎只认 updatedAt/rev，与存储无关）。PWA 在 Tauri 安卓包就绪后退役。

**存储演进路线**：当前 Dexie/IndexedDB → 原生端 SQLite（Tauri）→ 触发条件满足时 Web 端平滑切换 SQLite WASM（最终全平台一套 SQL）。切换成本已被架构隔离（数据真源在服务端，换端登录全量拉取即迁移；业务代码零改动）。**Web 端换存储的唯一真耦合是响应式查询层**——Phase 0 必须同时抽象统一查询 Hook（`useCollection`/`useRecord`），组件不得直接依赖 Dexie API。重新评估切换的触发条件：① 出现内存算不动的复杂聚合查询；② 原生端落地后希望双端共用一套 SQL 语义；③ SQLite WASM 在 Safari 稳定落地。

### 2.3 离线优先 + 多端同步（用户补充需求定案）

**原则：本地 IndexedDB 是唯一读写源，离线完全可用；在线时自动双向同步，冲突用 Last-Write-Wins。**

> **数据持久性模型（硬性设计原则）**：服务器（PocketBase/SQLite）是**数据真源**，本地 IndexedDB 定位为**可丢弃的离线工作副本**。浏览器「清除站点数据」会删掉 IndexedDB（清「缓存」则不会），因此任何单端本地数据都必须可随时丢弃重建：① 同步窗口尽量短（写入后 2s 防抖推送 + 30s 心跳，未同步数据最多滞留数秒）；② 登录/首启即全量拉取 workspace 数据与附件，被清端几分钟内完整重建；③ 附件真源在服务端文件存储，本地 Blob 可丢；④ 设置页提供 JSON/CSV/Markdown 全量导出兜底。

- **写入路径**：所有模块只写本地 → 写成功即返回（界面零等待）→ 变更进同步队列
- **记录级同步元数据**（所有业务表统一携带）：`updatedAt`（毫秒时间戳，每次写入刷新）、`deleted`（软删除）、`rev`（本地自增版本号）
- **同步协议**：
  1. 触发：应用启动 / 网络恢复（online 事件）/ 定时心跳 30s / 写入后防抖 2s
  2. 推送：按 `rev` 顺序上传本地未同步变更（按 workspace 隔离）
  3. 拉取：拉取远端 `updatedAt > lastSyncCursor` 的增量
  4. 合并：**LWW** —— 同 id 记录比较 `updatedAt`，新者胜，直接覆盖。不做字段级合并、不做 CRDT（两人同时编辑同一文件概率极低，产品上接受覆盖）
  5. 删除：软删除标记同步，两端各自物理清理 30 天前的墓碑
- **同步状态 UI**：顶栏「云糖实时同步」徽章 → 实装为三态：已同步（绿）/ 同步中 / 离线待同步（含待传条数）
- **云端后端（已定案）：自托管 PocketBase**，部署在用户自己的云服务器上，多端数据只与该服务器同步，不依赖任何第三方云服务。PocketBase 单二进制 + SQLite，自带用户认证、REST API、文件存储（凭证图片）、实时订阅与管理后台；我们用其 JS 扩展钩子实现 `push(changes)` / `pull(cursor)` 两个同步接口。前端静态文件与 API 同域部署（Nginx 反代），服务器备份 = 拷贝 SQLite 文件
- **多设备实况（2 人 × 电脑/手机 ≥4 端）的适配约定**：
  - 应用启动即调用 `navigator.storage.persist()` 申请持久化存储，防手机浏览器回收 IndexedDB；「数据与安全」页显示存储持久化状态
  - 统计数据（EXP/连击/奖杯进度）**不做成同步记录**，一律从源记录（HabitLog/事件流水）实时推导，杜绝 LWW 覆盖丢数据
  - 同步范围绑定 workspace（2 个成员账号 × 多端登录同一份团队数据），绑定 user 而非设备
  - 瞬态状态（专注计时进行中、UI 偏好）只存本地，不进同步队列
- **账号体系**：与工作区绑定，Collaborator 加入 workspace 即获得同步范围；本期先做「个人数据云端备份 + 双端同步」，成员协作邀请可后置

### 2.4 跨模块联动机制（系统灵魂）

**事件总线 + 奖杯引擎**，所有联动解耦为「发布 → 响应」：

| 事件 | 联动效果 |
|---|---|
| 完成深度专注 25min | 习惯"深度工作"自动打卡 + EXP + 触发奖杯检查 + 工作台连击更新 |
| 习惯打卡完成 | 待办自动生成/勾选 + EXP + 奖杯检查 |
| 记账（关联客户） | 客户详情页"关联账单"更新 + 待办"对账"联动 |
| 客户跟进记录 | 待办"今日 17:30 截止"倒计时 + 久未跟进权重变化 |
| 笔记 @提及实体 | 双向链接：客户详情/待办卡片/账本凭证可跳回笔记 |
| 速记便签 | 一键「转待办」或「归入团队笔记」 |
| EXP 达标 | Lv 升级 + 解锁奖杯 → PSN 风格弹窗（⌘S 生成海报） |

## 5.5 项目模块（Issue #10 定稿 · 已实装）

**项目 = 跨模块的「主题容器」**，承载三类用法：长期项目（里程碑+账+待办）、持续跟进（跟进+账+待办）、资料聚合（笔记归属）。不是一个字段，也不是某模块的附属。

**数据模型**（全部带 SyncMeta，参与同步）：

```
projects           { id, name, color, status: active|paused|archived,
                     customerId?, budget?, note?, createdAt }
projectMilestones  { id, projectId, name, dueAt?, weight,
                     status: planned|inProgress|done, sortOrder }
各模块可选弱引用（旧数据零迁移）：
  Transaction.projectId? / Todo.projectId? / Note.projectId? / Interaction.projectId?
```

**核心概念分层**：待办=执行引擎（一次性，做完就勾掉）；里程碑=阶段刻度（长期状态，参与加权进度）；跟进日志=过程流水（复用 Interaction，不新建表）。写记录前判断：要执行的→待办；阶段检查点→里程碑；过程小结→跟进日志。

**进度推导（不存快照，仓库铁律）**：有里程碑按 `Σ(done×weight)/Σ(weight)`；无里程碑 fallback 待办完成率；都无则 0。项目表不存任何聚合字段。

**边界**：客户是「人/组织」，项目是「事」——项目可不挂客户，一个客户可挂多个项目（客户详情页可下钻「名下项目」）；只归档资料用笔记文件夹，跨模块串联才用项目，两者并存。

**级联删除纪律**（照 deleteCustomerCascade / deleteTodoListCascade）：删项目时软删名下里程碑；账/待办/笔记/跟进是弱引用，只清 projectId 不删记录（账目不能因项目没了而消失）。

**同步接入**：`SYNC_TABLES` 加 projects/projectMilestones；`collections.json` 两个新 collection + 四表补 projectId；Dexie v7（projectId 全部建索引，级联查询走索引）。

## 八、风险与预案

| 风险 | 预案 |
|---|---|
| IndexedDB 附件（凭证图片）容量管理 | Blob 单独表 + 配额提示，超限引导导出归档 |
| 同步中断/半途失败 | 队列按 rev 断点续传，单条失败不阻塞队列；服务端幂等（按 id upsert） |
| LWW 时钟偏差（客户端时间不准） | 服务端收到即盖 server_received_at 做兜底排序；极端情况以服务端序为准 |
| 手机浏览器回收 IndexedDB（Safari 存储压力大时清库） | 启动即申请 persistent storage；设置页显示存储状态；本地数据有云端副本，被清后登录可全量拉回 |
| LWW 覆盖丢统计（多端同时改 Progress） | 统计一律从源记录推导，Progress 不参与同步（见 2.3 多设备约定） |

| 墓碑数据膨胀 | 软删除 30 天后两端各自物理清理 |
| 力导向图性能（百级节点） | d3-force tick 节流 + 视口裁剪，节点>200 分页展开 |
| CodeMirror 中文输入法兼容 | composition 事件处理，实测 IME 场景 |
| 奖杯条件误触发 | 引擎幂等设计，unlockedAt 唯一约束 + 事务 |
