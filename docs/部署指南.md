## 1. 上传并安装 PocketBase

```bash
# 本地：上传物料
scp dist/ server:/var/www/nexus/            # 前端静态文件（-r，或先 tar）
scp -r pb_setup/ server:/opt/nexus/pb_setup

# 服务器上
PB_VERSION=0.28.0    # 执行前到 GitHub Releases 核对最新版本，要求 >= 0.23
cd /opt/nexus
wget https://github.com/pocketbase/pocketbase/releases/download/v${PB_VERSION}/pocketbase_${PB_VERSION}_linux_amd64.zip
unzip pocketbase_${PB_VERSION}_linux_amd64.zip -d pocketbase
cp -r pb_setup/pb_hooks pocketbase/
cp pb_setup/backup.sh pocketbase/ && chmod +x pocketbase/backup.sh
cd pocketbase
./pocketbase superuser create admin@example.com <管理员密码>
```

## 2. systemd 常驻

```bash
sudo tee /etc/systemd/system/pocketbase.service <<'EOF'
[Unit]
Description=PocketBase (Nexus Workspace sync)
After=network.target

[Service]
Type=simple
User=pocketbase
WorkingDirectory=/opt/nexus/pocketbase
ExecStart=/opt/nexus/pocketbase/pocketbase serve --http=127.0.0.1:8090
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo useradd -r -s /usr/sbin/nologin pocketbase || true
sudo chown -R pocketbase:pocketbase /opt/nexus/pocketbase
sudo systemctl daemon-reload
sudo systemctl enable --now pocketbase
sudo systemctl status pocketbase   # active (running) 即可
```

导入 collections 并创建同步账号（见 `pb_setup/README.md` 第 2/3 节）：管理后台 `http://<IP>:8090/_/`（导入完成后建议在防火墙或 Nginx 层限制 `/_/` 与 `/api/` 之外的路径暴露）。

## 3. Nginx 反代：前端静态 + API 同域

```nginx
# /etc/nginx/sites-available/nexus
server {
    listen 80;
    server_name sync.example.com;          # 换成你的域名
    client_max_body_size 25m;              # 附件上传（pb 单文件上限 20MB）

    root /var/www/nexus;                   # dist/ 上传位置

    # 前端 SPA
    location / {
        try_files $uri $uri/ /index.html;
    }

    # /assets/ 静态资源长缓存（Vite 指纹文件名）
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # PocketBase API 同域反代（前端设置页只需填 https://sync.example.com）
    location /api/ {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # PocketBase 文件直链（附件还原走 /api/files/，已包含在 /api/ 内，无需单独配置）

    # 管理后台：仅放行你的常用出口 IP（可选但强烈建议）
    # location /_/ {
    #     allow <你的IP>;
    #     deny all;
    #     proxy_pass http://127.0.0.1:8090;
    # }
}

# 管理后台与 /api/ 同理都在 8090 上；上面 /api/ 已覆盖，/_/ 若无 IP 白名单需求可整体反代
```

```bash

```

## 6.5 AI Agent 桥（relay）

> Issue #33 后，relay 与前端**同源**（同源 `/relay`），不再需要独立端口给 Agent 直连、也不需要为它改 CSP
> （同源 WebSocket 由 `connect-src 'self'` 直接覆盖）。但「同源」指**对外路径**同源，relay 仍是一个 Node 进程。

**两种落位，按实际拓扑选其一**：

**甲 · 一体化（小规模 / 单机最省事）** —— 用一个进程同时托管 `dist/` 与 relay：

```bash
npm run build
HOST=127.0.0.1 PORT=9001 WORKHUB_RELAY_TOKEN="<≥16位随机串>" npm run serve
# 站点与 relay 同在 :9001，nginx 只需整体反代
```

**乙 · 分离式（本项目测试环境的实际形态）** —— 前端静态交给 nginx，relay 只跑自己那部分：

```bash
# systemd 单元 nexus-relay.service（WorkingDirectory = 仓库根）
HOST=127.0.0.1 PORT=9100 WORKHUB_RELAY_TOKEN="<token>" npm run serve
```

```nginx
# 宿主 nginx（前端静态在同文件的 location / 里）
location /relay {
    proxy_pass http://127.0.0.1:9100;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;   # relay 无周期性心跳，默认 60s 空闲会被掐断（表现为桥反复重连）
}
```

**三条不能省的配置**（踩过坑）：

1. `HOST=127.0.0.1` —— `serve.mjs` 默认绑 `0.0.0.0` 且自身没有 host 安全闸门，不设就绕过 nginx 直接暴露端口
2. `access_log off`（或在反代层关日志）—— 浏览器端点把 token 放在 URL query，否则凭证明文落 access.log
3. `proxy_read_timeout` 放大 —— 见上

**应用内**：系统设置 → **AI Agent 桥** → 启用 → **地址留空**（自动用当前站点，HTTPS 下自动推导 `wss://`）→ 填与控制台一致的 token。

> ⚠️ **token 必须在两侧一致**：relay 启动时打印的 token、页面「AI Agent 桥」里的 token、`~/.workhub/relay.json` 的 token
> 三者不同就连不上，且 UI **只显示「连接中…」无限重连、不给原因**。页面上那个输入框是**只读**的，
> 因此可行顺序只有一条：**先记下页面 token → 用它重启 relay**。

完整说明见 `docs/AI-Agent桥-一体化说明.md`；联调实测记录见 `docs/AI桥联调实测-20260915.md`。

## ⚠️ Schema 升级流程（应用每次新增字段/表时必做）

应用的数据模型演进（如 v4 新增 todoLists 表、todos.listId 字段）时，服务端 collections 必须同步升级，否则 PB 会**静默丢弃**未知字段（不报错）：

1. 本地 `pb_setup/collections.json` 已随代码更新
2. 重新导入：管理后台 → Settings → Import collections（或 API `PUT /api/collections/import`，superuser 鉴权，`deleteMissing: false`）
3. 已推送过的旧记录补字段：前端再执行一次「全量推送」（LWW 会用带新字段的本地版本覆盖服务端）

## 🛠 服务端升级实录（登录服务器后的完整操作步骤）

> 适用场景：应用代码已更新（如 Issue #34 亲密度、Issue #86 模块配置页），服务端 collections 落后 → 新字段被静默丢弃、配置读不到、多端不一致。
> 前置：服务器可 SSH 登录，PocketBase 由 systemd 托管（服务名以实际为准，本项目为 `pocketbase`）。

### 步骤 1 · 登录并确认现状

```bash
ssh <user>@8.153.19.221                 # 登录服务器（本项目别名 srv153）
systemctl status pocketbase             # 期望 active (running)
curl -s http://127.0.0.1:9002/api/health   # 期望 {"code":200,...}（PB 在 9002，9001 是宿主 nginx）
ls /opt/pocketbase                      # 确认实际部署路径（本项目 0.40.2 装在 /opt/pocketbase）
```

若 `systemctl status` 报 `Unit pocketbase.service could not be found`，用 `ps -ef | grep pocketbase` 找进程与工作目录。

### 步骤 2 · 先备份（数据真源，务必先备份）

```bash
cd /opt/pocketbase
./backup.sh                             # 产物落在 /opt/pocketbase/backups/<时间戳>/
ls -lt backups | head -3                # 确认最新备份目录已生成
```

### 步骤 3 · 拉取最新服务端物料

```bash
cd /opt/pocketbase
# 方式 A：从仓库拉（推荐，与代码同版本）
git clone --depth 1 <仓库地址> /tmp/workhub && cp -r /tmp/workhub/pb_setup/pb_hooks/* pb_hooks/
# 方式 B：本地 scp 上传
# scp -r pb_setup/ server:/opt/pocketbase/
```

`pb_hooks/main.pb.js` 必须同步更新，否则新表（moduleConfigs / customerGroups）不会被盖墓碑标记，服务端墓碑会无限增长。

### 步骤 4 · 导入 collections（补齐缺失表 / 字段）

管理后台 `https://dev.fpigeon.fun/_/` → 超管登录 → **Settings → Import collections** → 粘贴 `pb_setup/collections.json` 全文 → 确认。

或走 API（superuser token 鉴权，`deleteMissing: false` 保证不动多余表）：

```bash
# ① 取超管 token（把 <邮箱> <密码> 换成实际值，勿写入仓库）
TOKEN=$(curl -s -X POST http://127.0.0.1:9002/api/collections/_superusers/auth-with-password \
  -H 'Content-Type: application/json' \
  -d '{"identity":"<超管邮箱>","password":"<超管密码>"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# ② 导入（文件为 JSON 数组，直接作为 collections 字段发送）
#    注意内层引号必须转义，否则 shell 会把 JSON 拆坏
curl -s -X PUT http://127.0.0.1:9002/api/collections/import \
  -H "Authorization: $TOKEN" -H 'Content-Type: application/json' \
  -d "{\"collections\": $(cat pb_setup/collections.json), \"deleteMissing\": false}"
```

> 旧版 PB 的 import 接口为 `PUT /api/collections/import`，请求体直接是集合数组；以管理后台导入为准，API 仅作自动化备选。

导入后核对：`customers` 有 `intimacy` 且**不再有** `healthScore`（历史遗留字段，新代码不再写入）、`todos` 有 `sortOrder`、`noteFolders` 有 `tombstonePushed`，且 `module_configs` / `customerGroups` / `todoLists` / `noteFolders` / `projects` / `projectMilestones` 表都存在。

### 步骤 5 · 重启 PocketBase（让 pb_hooks 生效）

```bash
systemctl restart pocketbase
sleep 3 && systemctl status pocketbase --no-pager | head -5
journalctl -u pocketbase -n 30 --no-pager   # 无报错即正常
```

> 必须重启：`pb_hooks` 只在进程启动时加载，新增的墓碑盖戳钩子与每日清理 cron 不重启不生效。

### 步骤 6 · 补数据：前端执行一次「全量推送」

浏览器打开 `http://8.153.19.221:9001` → **系统设置 → 云端同步** → 填地址 `http://8.153.19.221:9001` + 同步账号 → **保存并连接** → **全量推送**。

原理：服务端 Schema 升级只加字段不补值，历史记录的新字段仍是空；全量推送用本地版本（LWW）覆盖服务端旧记录，把 `intimacy` / `sortOrder` / `moduleConfigs` 配置等补齐。

```bash

curl -s 'http://127.0.0.1:9002/api/collections/customers/records?perPage=1' \
```
